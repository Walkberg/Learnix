# Feature Specification: AI-assisted Study Generator

**Feature Branch**: `001-ai-study-generator`  
**Created**: 2025-11-04  
**Status**: Draft  
**Input**: User description: "Create an application that allows users to generate study sheets and quizzes from course texts, with the help of AI. Main features: automatic generation of course summaries; creation of quizzes and flashcards from summaries; ability to review and test knowledge; user and role management. MVP: 1. Authentication: login / logout; 2. Create study sheets from course text; 3. Create quizzes from a course; 4. Complete a quiz; 5. Logout."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Authenticate (Priority: P1)

As a user I want to sign in and sign out so I can access my personal courses, study sheets and quizzes.

**Why this priority**: Secure access is the entry point to all other features (creation, persistence, quotas).

**Independent Test**: Create an account (or use an existing account), sign in, then sign out; verify that private resources are accessible only when signed in.

**Acceptance Scenarios**:

1. **Given** a user is not signed in, **When** they provide valid credentials, **Then** they are authenticated and redirected to their home page.
2. **Given** a user is signed in, **When** they click "Logout", **Then** they are signed out and can no longer access protected pages.

---

### User Story 2 - Generate a study sheet from text (Priority: P1)

As a user I want to paste or import a course text and receive a concise study sheet automatically generated by the AI.

**Why this priority**: This is the core product value — turning course text into an immediately usable study aid.

**Independent Test**: Provide a typical course text (e.g., 1,000–3,000 words), request generation, and verify the presence of a title, a clear summary, and structured items (key points).

**Acceptance Scenarios**:

1. **Given** valid course text, **When** the user requests "Generate study sheet", **Then** the system returns a sheet containing a title, a summary (3–6 bullet points) and suggested flashcards.
2. **Given** empty or too-short text, **When** the user requests generation, **Then** the system displays a clear error message asking for more content.

---

### User Story 3 - Generate a quiz from a course (Priority: P2)

As a user I want to generate a quiz based on a course summary to test my knowledge.

**Why this priority**: Allows learners to assess knowledge and complements the study sheet.

**Independent Test**: From an existing study sheet, generate a quiz of X questions and verify that each question matches the requested type (MCQ or open) and has plausible answers.

**Acceptance Scenarios**:

1. **Given** a study sheet, **When** the user requests "Generate quiz (10 questions)", **Then** the system creates a quiz of 10 questions with multiple-choice or open questions according to configuration.
2. **Given** the user selects "MCQ - 4 choices", **When** the quiz is generated, **Then** each question has exactly 4 options with one correct answer.

---

### User Story 4 - Complete a quiz and view results (Priority: P2)

As a user I want to take the quiz, receive a score and see a breakdown of correct/incorrect answers.

**Why this priority**: Measuring progress and providing immediate feedback increases engagement.

**Independent Test**: Complete a saved quiz, submit answers, verify score calculation and display of corrections.

**Acceptance Scenarios**:

1. **Given** an uncompleted quiz, **When** the user submits their answers, **Then** the system displays the score, the list of answers and suggestions for improvement.

---

### Edge Cases

- Very long course text (>50k words) — the system should indicate a limit or suggest splitting the text.
- Unreadable content / unknown format — display an error and provide format guidance.
- AI service failure (slow response or error) — show a clear message and offer to retry later.
- Quotas reached (Free account) — refuse creation and explain the limit and the option to upgrade to Premium.

# Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The system MUST allow a user to register and sign in (email/username + password).
- **FR-002**: The system MUST allow creating a course with a title and source text.
- **FR-003**: The system MUST automatically generate a concise study sheet from the provided text.
- **FR-004**: The system MUST allow generating one or more quizzes based on the study sheet or course text, with parameters (number of questions, MCQ/open).
- **FR-005**: The system MUST allow a user to complete a quiz, submit answers and receive a summary and score.
- **FR-006**: The system MUST enforce quotas based on role (Free: up to 3 courses and 3 quizzes; Premium: unlimited).
- **FR-007**: The system MUST display clear user-facing error messages for invalid text, quota limits, or AI unavailability.
- **FR-008**: Critical actions (create course/quiz, submit quiz) MUST be persisted and associated with the user.

### Key Entities *(include if feature involves data)*

- **User**: id, display_name, email (business-level), role (Free / Premium), signup_date
- **Course**: id, author (User), title, source_text, created_at
- **Summary / Study Sheet**: id, linked_to Course, summary_title, key_points, suggested_flashcards
- **Quiz**: id, linked_to Course or Summary, question_list, parameters (count, type)
- **Question**: id, type (MCQ / open), prompt, options (for MCQ), correct_answer
- **Flashcard**: id, prompt, answer

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Users can generate a complete study sheet from a typical text (1–3k words) in under 30 seconds in 95% of cases.
- **SC-002**: At least 90% of generated quizzes contain the requested number of questions and, for MCQs, the correct number of properly formatted options.
- **SC-003**: Users completing a quiz report that the quiz is relevant to the content in ≥80% of sessions (simple user feedback).
- **SC-004**: AI-side errors are presented to users with a clear recommendation 100% of the time (no raw technical messages).

## Assumptions

- Authentication: default to standard email + password (session management) for the MVP.
- Quotas: Free / Premium rules from `Plan.md` apply (Free: 3 courses / 3 quizzes; Premium: unlimited).
- AI limits: text size limits will be applied (e.g., 50k words) and the UI will suggest splitting content if needed.
- The `.specify` script created the `specs/001-ai-study-generator` directory and this file; repo-relative paths are valid.

## Dependencies

- AI service for summary generation and question formulation.
- User authentication system and role/quota management.

## Development Requirements

### Testing Strategy
- All features MUST be implemented using Test-Driven Development (TDD) approach:
  - Write failing tests first for each new functionality
  - Implement minimal code to make tests pass
  - Refactor while maintaining test coverage
- Unit tests MUST be written for:
  - All API endpoints
  - Service layer business logic
  - Data model validations
  - UI components
- Integration tests MUST be written for:
  - API-to-database flows
  - Authentication flows
  - AI service integration
- End-to-end tests MUST cover:
  - Critical user journeys from User Scenarios
  - Edge cases described in specification
